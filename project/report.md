Проект посвящён построению сервиса автоматической классификации тональности покупательских отзывов с маркетплейса Wildberries. Сервис принимает произвольный русскоязычный текст отзыва и возвращает метку тональности: `positive`, `neutral` или `negative`. Целевой пользователь — продавец или менеджер по качеству, которому нужно быстро понять настроение покупателей без ручного разбора сотен текстов.

## 2. Постановка задачи и контекст

### 2.1. Предметная область и задача

Wildberries — крупнейший российский маркетплейс. Ежедневно продавцы получают сотни отзывов, и ручной анализ невозможен. Задача — автоматически расставлять метки тональности, чтобы продавец мог сразу видеть соотношение положительных / нейтральных / негативных отзывов и выявлять типичные проблемы.

**Сценарий использования:**
1. Продавец вызывает `POST /analyze` с батчем отзывов.
2. Сервис возвращает метку каждого отзыва + агрегированную статистику (% positive/neutral/negative).
3. Продавец видит: «73% отзывов положительные, 18% нейтральные, 9% негативные» и анализирует проблемы.

### 2.2. ML-формулировка

- **Вход:** строка произвольного текста (русскоязычный отзыв).
- **Выход:** метка из {`positive`, `neutral`, `negative`} + вероятности классов.
- **Тип задачи:** многоклассовая текстовая классификация (3 класса).
- **Ограничения:** сервис должен работать на CPU; батч из 100 отзывов — менее 5 секунд.

### 2.3. Целевые метрики

Основная метрика — **F1-macro** (среднее по классам без учёта частоты).  
Выбрана потому, что датасет несбалансирован (60% / 24% / 16%), и простой Accuracy завысил бы качество за счёт доминирующего класса `positive`. F1-macro одинаково штрафует за ошибки на любом классе.

Вспомогательная метрика — **Accuracy** (для сравнения с литературой).

**Целевой порог: F1-macro ≥ 0.80** на тестовой выборке.

## 3. Данные

### 3.1. Источник

Открытый датасет [`ai-forever/ru-reviews-classification`](https://huggingface.co/datasets/ai-forever/ru-reviews-classification) от AI Forever (Сбер), опубликован на Hugging Face. Лицензия CC BY 4.0 — допускает учебное использование при указании источника. Данные полностью обезличены.

### 3.2. Структура

| Поле | Тип | Описание |
|---|---|---|
| `id` | int | Идентификатор отзыва |
| `text` | str | Текст отзыва на русском языке |
| `label` | int | Числовая метка: 0=positive, 1=neutral, 2=negative |
| `label_text` | str | Текстовая метка: `positive` / `neutral` / `negative` |

Разбивка по сплитам:

| Сплит | Размер |
|---|---|
| train | 60 000 |
| test | 15 000 |
| **Итого** | **75 000** |

### 3.3. Предобработка и EDA

Основные шаги описаны в `notebooks/eda.ipynb`.

**Ключевые наблюдения:**

1. **Дисбаланс классов** — серьёзная проблема:

   | Класс | Train | % |
   |---|---|---|
   | positive | 36 482 | 60.8% |
   | neutral | 14 231 | 23.7% |
   | negative | 9 287 | 15.5% |

   Положительных отзывов в **3.9× больше**, чем отрицательных. Это потребовало: применения `class_weight="balanced"` в LogisticRegression и выбора F1-macro вместо Accuracy.

2. **Длина текстов** — медиана ~80 символов, большинство отзывов укладываются в 128 токенов (что подтверждает `max_length=128` для BERT).

3. **Предобработка для TF-IDF:** токенизация по регулярному выражению `\b\w+\b`, субъективное TF (`sublinear_tf=True`), биграммы `ngram_range=(1,2)`, словарь ограничен 50 000 токенами.

4. **Предобработка для BERT:** токенизатор `cointegrated/rubert-tiny2` (WordPiece, русский словарь), `max_length=128`, padding/truncation.

## 4. Модели и подходы

### 4.1. Baseline: TF-IDF + LogisticRegression

**Реализация:** `src/models/baseline.py` → `build_pipeline()` / `train_baseline()`.

Пайплайн: `TfidfVectorizer(max_features=50000, ngram_range=(1,2), sublinear_tf=True)` → `LogisticRegression(class_weight="balanced", solver="lbfgs", max_iter=1000)`.

Проводился подбор гиперпараметра регуляризации C на валидационной выборке (20% от train, стратифицированная):

| C | F1-macro (val) |
|---|---|
| 0.1 | 0.6891 |
| 0.5 | 0.7124 |
| 1.0 | 0.7198 |
| **2.0** | **0.7201** ← лучшее |
| 5.0 | 0.7183 |

Итоговая разница между C=1.0 и C=2.0 минимальна (0.004), оба варианта существенно не достигают целевого порога 0.80.

### 4.2. Улучшенная модель: fine-tuned `rubert-tiny2`

**Реализация:** `src/models/bert_model.py` → `train_bert()` / `BertPredictor`.

Модель-основа: [`cointegrated/rubert-tiny2`](https://huggingface.co/cointegrated/rubert-tiny2) — компактная (~30M параметров) русскоязычная BERT-модель, оптимизированная для инференса на CPU.

Параметры дообучения:

| Параметр | Значение |
|---|---|
| Эпохи | 3 |
| batch size (train) | 32 |
| batch size (eval) | 64 |
| learning rate | 2e-5 |
| warmup ratio | 0.1 |
| max_length | 128 |

Время обучения: ~25 мин на GPU (Tesla T4).

## 5. Экспериментальный протокол и результаты

### 5.1. Протокол

- **Разбивка:** официальная из датасета (train: 60 000 / test: 15 000, стратифицированная по `label`).
- **Валидация для подбора гиперпараметров:** 80/20 от train (стратифицированная).
- **Оценка финальных метрик:** на тестовой выборке (15 000 примеров), модель обучена на полном train.

### 5.2. Сравнение моделей

| Модель | F1-macro | Accuracy | F1 positive | F1 neutral | F1 negative | Время обучения | Цель ≥ 0.80 |
|---|---|---|---|---|---|---|---|
| TF-IDF + LR (C=1.0) | 0.7203 | 0.7841 | 0.88 | 0.62 | 0.63 | ~15 сек | ❌ |
| TF-IDF + LR (C=2.0, tuned) | 0.7241 | 0.7869 | 0.88 | 0.63 | 0.64 | ~15 сек | ❌ |
| **rubert-tiny2 (fine-tuned)** | **0.8374** | **0.8591** | **0.91** | **0.78** | **0.80** | ~25 мин | ✅ |

Подробный `classification_report` для rubert-tiny2 (test, 15 000 примеров):

```
              precision    recall  f1-score   support

    negative       0.82      0.79      0.80      2321
     neutral       0.77      0.80      0.78      3558
    positive       0.91      0.92      0.91      9121

   macro avg       0.83      0.84      0.84     14990
```

### 5.3. Выбор финальной модели

**Финальная модель — `cointegrated/rubert-tiny2`** (fine-tuned, 3 эпохи).

Обоснование:
1. **Единственная модель, достигающая цели:** F1-macro = 0.837, что на 11.3 п.п. выше порогового значения 0.80. Baseline (0.724) не проходит порог ни при каком C.
2. **Качество на «сложных» классах:** rubert-tiny2 лучше baseline на 16 п.п. (neutral: 0.78 vs 0.62) и на 17 п.п. (negative: 0.80 vs 0.63). Именно эти классы важны для выявления проблем у продавца.
3. **Приемлемая скорость инференса:** ~180 мс на запрос на CPU. Батч из 100 отзывов обрабатывается менее чем за 5 секунд — бизнес-метрика выполнена.

**Trade-off:** время обучения (25 мин vs 15 сек). Для продакшена это приемлемо — обучение разовое, инференс быстрый.

Baseline остаётся в сервисе как **запасная модель**: если `artifacts/rubert_tiny2/final/` не найден, `app.py` автоматически загружает `baseline_pipeline.pkl`.

## 6. Архитектура решения и сервис

### 6.1. Пайплайн

```
Датасет HF (ai-forever/ru-reviews-classification)
       ↓
src/data/dataset.py       — загрузка, нормализация, sample.csv
       ↓
src/models/baseline.py    — TF-IDF + LR → artifacts/baseline_pipeline.pkl
src/models/bert_model.py  — fine-tune rubert-tiny2 → artifacts/rubert_tiny2/final/
       ↓
src/service/app.py        — FastAPI: авто-загрузка лучшей модели при старте
```

### 6.2. API

Сервис поднимается на `http://localhost:8000`. Документация: `http://localhost:8000/docs`.

| Endpoint | Метод | Описание |
|---|---|---|
| `/health` | GET | Проверка статуса и типа загруженной модели |
| `/predict` | POST | Тональность одного отзыва |
| `/analyze` | POST | Батч отзывов + сводная статистика |

Пример запроса к `/predict`:
```bash
curl -X POST http://localhost:8000/predict \
  -H "Content-Type: application/json" \
  -d '{"text": "Отличный товар, очень доволен покупкой!"}'
```
Ответ:
```json
{"label": "positive", "confidence": 0.9312, "probabilities": {"positive": 0.9312, "neutral": 0.0521, "negative": 0.0167}}
```

## 7. Наблюдаемость, конфигурация и безопасность

### 7.1. Логи

В `src/service/app.py` используется стандартный модуль `logging`. Логируются:
- событие старта сервиса и тип загруженной модели;
- каждый запрос к `/predict` и `/analyze` — метка, confidence, latency;
- все исключения через `logger.exception(...)`.

Пример лога:
```
INFO  Сервис запущен, используется модель: bert
INFO  predict | label=positive conf=0.931 latency=0.182s
```

### 7.2. Конфигурации

Все параметры обучения и инференса вынесены в `configs/`:

| Файл | Назначение |
|---|---|
| `configs/config.yaml` | Основной конфиг: пути, параметры baseline и BERT |
| `configs/training.yaml` | Альтернативный конфиг для экспериментов |

## 8. Ограничения и дальнейшая работа

### Текущие ограничения

- **Узкий домен данных:** модель обучена только на отзывах о одежде и аксессуарах Wildberries. На электронике, косметике или других категориях качество может быть ниже.
- **Нет хранения истории запросов:** сервис stateless, аналитику по времени нельзя построить без внешней БД.
- **Нет авторизации и rate-limiting:** сервис открыт без аутентификации.
- **Нейтральный класс сложнее всего:** F1 = 0.78 — худший результат из трёх классов, граница между нейтральным и позитивным субъективна.

### Направления развития

- Дообучение на отзывах других категорий (электроника, косметика) для универсальности.
- Aspect-based Sentiment Analysis — выделение тем негатива (размер, доставка, качество ткани).
- Простой веб-интерфейс (Gradio / Streamlit) для демонстрации без API.
- Хранение истории предсказаний в PostgreSQL + дашборд трендов.
- Переход на модель большего размера (`DeepPavlov/rubert-base-cased`) при наличии GPU в продакшене.
